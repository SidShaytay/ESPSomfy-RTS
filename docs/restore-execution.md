# Checked restore execution

This feature branch connects restore execution to the existing claimed restore source. It does not create another updater owner or change the 80-byte queue marker. Selected sections use the staged checked writer from SelectedSettingsRestore. Every requested record and carried field is qualified before counter promotion or model adoption. This coupled feature remains held from main until all requested-record and hardware-ownership guards plus final joint review/tests complete.

Loop execution seals the empty producer queue, then pauses the quiescent radio under the same source. Accepted commands are never flushed, including STOP. Both capabilities remain held through counter preflight/promotion and model adoption. The actual ConfigFile boundary requires the exact retained context and radio token, not an earlier idle snapshot. A refusal before any counter write or adoption preserves the old trusted model. A counter write attempt followed by failure quarantines the model without claiming rollback.

Cleanup restores the radio, reopens the queue, removes the owned temporary file, and releases the resource claim before an exact-source restart handoff. Busy radio cleanup retains the source claim and file-resource ownership across expiry; the normal transfer cleanup cannot steal them. Later cleanup success does not retry restore or schedule a restart. Unavailable radio cleanup is terminal and visible. Stale ownership or failed file cleanup retains the faulted context rather than touching a replacement source. Status stores only bounded result facts and a fresh boot nonce plus source generation, without backup values.

`tools/test-restore-execution.sh` uses the actual GitUpdate owner/lifecycle and queue admission methods with fake physical radio, file and domain effects. It exercises deadline cleanup, stale/replaced sources, accepted queue work, counter uncertainty, malformed completion certificates and failed temporary-file cleanup. `tools/test-application-upload.sh` exercises actual upload and queue consumers in both generic and bundled variants. These offline checks do not qualify RF, motor movement, power-loss durability or physical cleanup timing.

The generic separate web-image workflow still needs checked unmount before raw filesystem SDK writes, owned cleanup/remount without formatting and checked current-model persistence. Fake upload success does not establish those properties. Canonical bundled boards continue to refuse that separate image route early.

The browser's 202 response contains decimal-string `bootSession` and `generation` fields. It is an admission response, not completion. Authenticated `/restoreStatus` requests must match both exactly; malformed identities fail and a replacement job or reboot makes the old identity stale. Queue publication failure marks only that cached queued generation refused. Disconnect after the source has entered queued ownership preserves its existing one-shot FIFO behavior.

The browser polls only the returned identity, at most 120 requests, with a five-second per-request timeout. Pending cleanup never causes an early model refresh or a completion claim. A terminal result displays the bounded server reason and refreshes actual model state if adoption occurred, including partial results. Close stops observation only. Authentication failure, stale identity, network failure and the polling bound never resubmit the backup or request a restart. Local browser rendering qualification remains separate from the JavaScript VM checks.

Restore authority is bound to the existing synchronized Security settings history. The first body chunk captures that history across a fresh authentication check; completion and loop admission reject replacement, same-value save, ABA history changes or unavailable security. Only the exact owned source carries the private witness. No credential or reconstructed client token is cached. Loop admission consumes the grant immediately before synchronous adoption, so the restore's own history invalidation does not revoke decreasing-authority cleanup. HTTP disconnect remains distinct from security replacement and retains the established queued-source behavior.

Selected restore reparses the header in opt-in checked mode before deciding same-board Ethernet ownership. Truncated identifiers, overflowed numbers and missing fields cannot qualify merely because legacy loading would have defaulted them. The ordinary boot parser keeps its legacy compatibility. The immutable settings tail is prepared before counter I/O, then the same reader is rewound to adopt the model. Projected GPIO checks count physical owners in that same immutable future model and use the prepared radio/Ethernet owners. Unknown ownership refuses assigned physical pads; RF-only and unset pads do not require an invented owner. Actual GPIO setup follows the settings/radio apply attempt and uses the resulting current ownership, including reported partial radio adoption.

A model adoption attempt emits one model-persistence event using this operation's file result, including applied/file-failed outcomes. Before producer admission reopens it retires the old socket identities and closes those transports. They reconnect with the same credentials and receive the normal fresh initial sync; this does not force a new login or add protocol messages. Retirement is identity-scoped and cannot be cleared by an old NEXT or sync completion. Mutation admission checks that identity inside the existing producer span, then checks it again before loop execution; refused queued edit/save payloads are freed once. The direct raw socket publisher shares the producer span and records a mutation only after scheduler acceptance. An empty restored model consequently removes old browser identities through the ordinary initial sync.

Broker refresh uses the existing disconnect and deferred ordinary-loop reconnection, preserves suspension, and leaves discovery-deletion policy unchanged. When the staged MQTT result already certifies adoption and completion of that deferred hook, model completion avoids duplicating it. Notification delivery cannot grant, retry or prevent resource cleanup or restart admission.
