# Settings durability and explicit reconciliation

The loop-owned `SettingsDurability` ledger records known partial settings writes during the current boot. It stores eight namespace bits, an uncertainty epoch and an exhaustion flag; no setting values, credentials or NVS handles. It does not provide transaction rollback or recovery after an unexpected power loss.

CFG is one namespace shared by general and connection settings. The remaining namespaces are NTP, WIFI, ETH, IP, MQTT, SEC and CC1101. Every checked full settings writer records its result before returning. A verified full namespace rewrite clears only that namespace. A failed write before any successful set preserves existing uncertainty. A partial write marks uncertainty and advances the epoch. Successful reconciliation never rewinds that epoch. Operational radio initialization markers, ordinary rolling codes and LCD preferences do not clear settings uncertainty.

A staged multi-part settings apply leaves running values unchanged on failure. Therefore, when a later part fails, every earlier successfully persisted draft namespace is marked uncertain again. An unrelated successful save cannot clear those bits. A complete save still updates running values and notifies completion/history, but `settings_apply_result_t::restartBlocked` reports outstanding uncertainty and suppresses its restart decision before completion. The socket reply uses the existing description and `rebooting=false`; form notices belong to the separate UI integration.

`reconcileRunningDeviceSettings()` is an internal loop-owned backend operation, callable only after fresh administrator admission. There is no route or UI command wired here. It explicitly saves **CURRENT RUNNING settings**, not an old edit or backup. It attempts only uncertain namespaces, reports requested/reconciled/remaining masks and a checked persistence result, and never requests a restart. Each successfully rewritten namespace refreshes the affected section history even when another namespace fails; SEC completion refreshes security history and the existing client reauthentication behavior. CFG refreshes both general and network histories. No hostname, NTP, MQTT or radio apply is replayed.

Radio reconciliation normalizes a copy, preserves the checked stored `radioInit` operational marker, and runs the same full namespace writer. An absent marker retains the existing boot default of true. A failed namespace open, failed read, wrong type or value outside 0/1 refuses reconciliation without writing. It never calls `setConfig()`, initializes radio hardware, submits RF/GPIO commands or modifies rolling codes.

This backend slice does not yet protect every restart or repair restore's ignored persistence outcomes. The next integration must bind all restart intents to the uncertainty epoch, invalidate old intents on any later uncertainty, check settings and dirty-model persistence before any shutdown, and never resurrect an old restart after a successful retry. Restore requires its own truthful checked result and staging integration. Updater installation/startup remain inactive. No physical access or live operation is authorized by this document.

Native regressions cover namespace isolation and CFG aliasing, actual writer partial failures, failed composite drafts, saved-but-blocked completion, running-value reconciliation, partial failure aggregation, history notifications, preserved radio markers and zero runtime effects. Firmware builds additionally check production DeviceOps and radio declarations; fake tests make no physical qualification claim.
