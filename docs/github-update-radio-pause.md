# Radio pause for an installation

The updater uses the existing radio and scheduler locks plus one receive-state mux. It does not flush a command, send STOP, change a counter or initialize new hardware to make admission succeed. This checkpoint supplies the actual pause/resume boundary; no installer or restore caller is enabled by it. The existing quarantined-model loop uses the memory-only receive servicing described below.

`updateActivity(out)` tries the radio and scheduler locks without waiting. A busy observation leaves `out` unchanged. Both radio and scheduler mutexes must exist before any new update API can grant or confirm pause permission, including an intentionally disabled radio; legacy null-mutex wrappers remain unchanged for other callers. Its ready state respects intentional radio disablement. Scheduler work includes queued/delayed/taken jobs and unobserved outcomes; admission also checks counter work, the raw repeater FIFO, frequency scan, completed RX FIFO and partial-frame decoder state.

`pauseForInstall(token)` requires an empty token and an idle observation under the radio → TX → RX lock order. It seals the empty scheduler without calling the flushing suspend API. It sets receive-paused under the ISR mux before detaching the interrupt, so an ISR already waiting cannot enqueue a frame after the snapshot. The receive FIFO and decoder are not cleared. Partial frames must finish or be rejected by ordinary decoding; the updater does not discard them to force progress.

The ISR, receive FIFO pop, initial FIFO setup and shared decoder reads now use the same receive mux. Pulse decoding and FIFO copies remain memory-only under the mux. Full frame decoding/model events, logging and GPIO/SPI driver calls run outside it. Edge clocks are sampled before taking the ISR lock; the noise path releases it before disabling the GPIO interrupt. Receive-enable helpers refuse while paused. Existing scan method bodies are unchanged; the separately reviewed scan feature can use this activity/mux rather than introduce another receive guard.

`installPauseHeld(token)` checks exact generation and the retained seal. `resumeAfterInstall(token)` returns resumed, unavailable, busy or stale, preserving the token on busy and refusing old tokens. It preserves the prior receive state when configuration revision is unchanged. An explicitly applied configuration revision instead determines whether the current enabled/hardware state can receive. Availability stays hidden throughout the pause and RX restoration; only then does it release the TX seal and publish availability. It never resumes a queued transmission, changes GPIO command mapping or retries radio initialization. Failed RX restoration is reported unavailable. The capability remains transient and cannot wrap its generation.

`CXX=g++ bash tools/test-radio-update.sh` compiles the production admission/ISR/receive methods with the actual scheduler and pulse decoder, substituting only physical hardware/locks. It covers pending RX/partial/repeater/scan/counter and waiting/taken/outcome TX, exact tokens, busy/unavailable resume, disabled-radio preservation, actual FIFO initialization with a log sink asserting the mux is not held, noise interrupt-disable placement and an ISR arriving during detach. Removing the paused-ISR guard fails that race regression. These tests establish no physical RF timing, reception, motor or rollback qualification.

`pauseForRestore(token)` reuses the same generation and seal. It requires the same observed empty/quiet resources but permits unavailable radio hardware so an explicit restore can repair configuration. `canPause()` still requires hardware readiness for installation; `quiescent()` deliberately does not. Receive enable/reattach serializes through the existing recursive radio mutex and refuses the pause before touching GPIO/SPI. Restoring new radio settings while paused cannot expose availability or attach RX early. Busy cleanup retains the capability and both caller-owned resources; it is not a successful unwind.

While the model is quarantined, `serviceUntrustedReceive()` discards only the bounded RX FIFO and partial decoder memory under the receive mux. It does not decode/emit frames, update a model/counter, schedule a repeater or touch GPIO/SPI/NVS. This lets explicit recovery reach idle admission instead of remaining blocked by an unprocessed receive backlog. It is a no-op for trusted models or an already retained radio pause. Trusted receive processing and accepted TX/repeater work are unchanged.
