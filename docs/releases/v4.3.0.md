# v4.3.0: GitHub updates, guided pairing and battery care in the web UI

This release follows v4.2.2 for the LILYGO T-Embed CC1101 and CC1101 Plus. Both boards use the same `lilygo-t-embed-cc1101` firmware, which includes the web interface.

## Added

- **GitHub updates from the web UI** (System → Firmware → GitHub releases). Check for a newer stable release and install it from the browser. The controller uses the same updater as the LCD: it verifies the release, saves your shades, restarts, and rolls back on its own if the new firmware doesn't start properly. Nothing is checked or installed automatically.
- **Guided pairing in the web UI.** Pairing and unpairing are now three steps: open the motor's memory with an existing remote, send Prog (with a repeat count), then confirm the second jog before the shade is marked as paired. Nothing is sent until you press Send.
- **Battery level in the web UI** on boards with a battery.
- **Battery charge limit**: 100%, 90%, 80%, 70% or 60%. For a controller that runs on USB all the time, **60% is recommended**: it is the lowest the charger allows and gives the battery the longest life. 100% stays the default and leaves the charger untouched. See [battery charge limit](../battery-charge-limit.md).

## Install

If you already run a tagged v4.x LILYGO build, use the LCD updater, the new web updater, or a firmware-only upload. Your settings and rolling-code counters are kept. A development build (one not built from a release tag) can't take GitHub releases; install this release once by firmware-only upload or USB. Coming from another firmware, read [first installation](../first-install.md) first. Don't erase the flash or use a factory image.

Protocol 2 gains two ops (`gitUpdate` 60 and `battery` 61); existing ops are unchanged, so the cjkas-compatible Home Assistant integration 3.0.0 or newer still works. The charge limit and the web updater are covered by native and browser-side tests; the charge limit's charger writes have not yet been measured on a board with a meter.
