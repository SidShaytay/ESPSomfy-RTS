# 4.5.1 — LCD repeat cancellation checkpoint

Back now cancels the remaining radio repeats of an accepted everyday LCD action. Session expiry, target/configuration changes, display recovery and request timeout also cancel remaining repeats. The active message stays visible while the exact request is pending.

Movement can continue after repeats end. The separate STOP action remains available for the same target under the existing security rules, including the original continuing-movement grace period. Cancelling repeats sends no automatic MY/STOP command.

Each newly confirmed LCD action still sends a fresh command and rolling code. Changed address, radio protocol, bit length or step size cannot reuse a stale frame. Ordinary controls, wired GPIO and dedicated programming batches retain their existing behavior.

This checkpoint also adds numeric updater memory diagnostics to the existing private serial log. The clean, locally tagged build has a stable release identity, satisfying that prerequisite for GitHub checking. Published compatible repository assets and physical TLS/staging qualification remain separate requirements.

## Remaining acceptance

- The interface still starts a confirmed finite batch. Hold/release input awaits the interaction decision; Back cancellation does not complete that requirement.
- Separate/Euro wired-relay tilt remains unavailable pending the support/scope decision; settings and ordinary lift controls are preserved.
- Combined hardware TLS/staging/edit/reconnect/long-idle measurements and hands-on encoder verification remain open. Offline tests do not establish physical motor/RF behavior.

The shared CC1101/CC1101 Plus image bundles controller, LCD and web assets. A firmware-only update preserves the separate LittleFS configuration and counters. Local preparation of this checkpoint does not publish a GitHub release or authorize RF/motor commands.
