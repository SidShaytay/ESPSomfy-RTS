# 4.6.0 — hold to send, release to end repeats

Everyday LCD repeat actions now require holding the knob on **Hold to send** after reviewing the target, action, step size and repeat count. A short tap sends nothing. After a stable 800 ms hold, the controller sends the reviewed finite batch; releasing the knob ends its remaining repeats. Release does not send STOP or MY: use the separate STOP action if the shutter must stop moving.

The hold must begin on a fully displayed, authorized review. Waking the display, changing the target or settings, losing authorization, pressing Back or reaching the timeout cancels the pending gesture or its remaining work. Completion and refusal remain visible while the knob is held; the gesture cannot start another batch until released. Existing explicit one-shot, favourite-programming and pairing flows retain their reviewed behavior.

The shared CC1101/CC1101 Plus firmware contains the controller, LCD and matching web UI. Firmware-only updates preserve private LittleFS configuration and the previous application slot; the legacy partition label `spiffs` does not change the filesystem format. Release automation also accepts already-versioned source without attempting an empty version commit.

Separate/Euro wired-relay tilt settings remain saved/editable, with ordinary supported lift and RF/GP_Remote behavior preserved. Tilt is unavailable for those two relay modes because the original web-backed relay driver has no mapping for them; this is a pre-existing backend limitation, not missing LCD configuration or a new driver/waiver requirement.

This candidate does not close issue #25. The remaining physical encoder, GitHub download and combined-load qualification remain open. Preparing local artifacts does not publish a GitHub release or qualify RF/motor behavior.
