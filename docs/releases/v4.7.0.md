# 4.7.0 ALPHA / preview — daily Quick access

**ALPHA / preview — applies to all builds currently produced by this fork.**

> WARNING: Please do not load these builds, these are still a preview of the final approach.

An actual controller GitHub download and installation has **never yet completed**.
Host/offline tests and successful desktop asset downloads do not prove that path.
See the [remaining qualification](../lcd-completion-qualification.md).

Release **4.7.0** is a GitHub **ALPHA prerelease**. The current stable updater rejects
prereleases. A separate LCD **Check alpha previews** option is not implemented;
its design awaits Sid's choice.

Quick access shows three pinned devices or groups together. Each opens the existing controls with STOP selected when supported, without sending a command. Back from shortcut controls returns directly to Quick access. **Browse & settings** retains the full room/device/group hierarchy and administration, settings and system workflows.

**Manage shortcuts** pins, removes or reorders the three slots using the configured web credential. Changes stay in a draft until an explicit default-Cancel Save review. Saving checks authorization and configuration again, commits one separate LCD preference and verifies it by reading it back. Browsing never writes preferences or changes motor favourites, configuration or counters.

Without saved preferences, group ID 1 and device IDs 1 and 2 are suggested when present. Saved empty slots remain empty; corrupt or unreadable preferences do not silently become suggestions. Shortcuts follow current names and refuse a missing target or a changed radio identity.

The bounded redraw scheduling from 4.6.1 and existing authentication, STOP grace and hold/release safeguards remain. Controller, LCD and web assets use the same version in one firmware image. Physical response and deployment evidence are recorded separately from host checks.
