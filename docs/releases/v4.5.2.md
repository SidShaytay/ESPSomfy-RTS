# 4.5.2 — observable boot confirmation

This checkpoint includes the LCD repeat cancellation and release identity described in the [4.5.1 notes](v4.5.1.md). It adds the fixed private serial event `OTA health confirmed=1` after the SDK successfully validates the updated firmware. The event remains available at the normal log level, allowing confirmation to be observed while leaving the pending application undisturbed.

The health policy is unchanged: confirmation still requires the continuous healthy interval. An SDK confirmation failure never emits the success event. The 4.5.1 tag and artifacts remain preserved as an unflashed local preparation checkpoint.

Hold/release input, the separate/Euro wired-relay tilt decision and the remaining physical qualification are still open. Preparing this checkpoint does not publish a release or authorize RF/motor commands.
