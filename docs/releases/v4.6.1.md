# 4.6.1 — faster LCD redraw

The LCD now skips unchanged screen bands immediately and sends several changed bands per controller-loop pass. Previously, scanning a 170-row screen required 43 separate loop passes, visibly delaying menu updates and the completed-screen input guard.

Each SPI transfer remains four rows with the existing nonblocking bus lock released after every transfer. A flush admits at most eight changed bands within an 8 ms admission budget; only unchanged-band validation may continue to the 10 ms work limit. A busy bus keeps the unsent band pending. Action authorization, completed-frame privacy, STOP and repeat-release cancellation retain their existing checks.

Realistic host timing reproduces the old delay and verifies the new bounds. With 1.5 ms modeled transfers and a 32 ms loop gap, remaining completion after the input tick is 238 ms for a menu transition and 118 ms for a selection change. These are modeled results; physical response remains a separate check.

Controller, LCD and matching web UI remain one firmware image. Configuration and counters stay separate and are preserved. No HA integration update is required for existing shutter controls/state; HA's upstream firmware-notification feed is a separate optional integration change.
