# v4.2.2: shutter calibration, group positions and Wi-Fi recovery

This release follows v4.1.0 for the LILYGO T-Embed CC1101 and CC1101 Plus. Both boards use the same `lilygo-t-embed-cc1101` firmware, which includes the web interface. It also includes the LILYGO board support that cjkas merged upstream ([cjkas/ESPSomfy-RTS#133](https://github.com/cjkas/ESPSomfy-RTS/pull/133)).

## Added

- Guided shutter calibration from the web UI and the LCD (each device's More menu). It measures take-up, travel in each direction, settling and direction changes from real radio start and stop times. Direct-drive covers skip the mechanical steps.
- Saved calibration is used for both individual and group moves. Group percentages start members together and stop each one at its own time.
- Optional task-stack measurement for diagnostics.

## Fixed

- **Wi-Fi recovery:** if the access point restarts or changes channel, and the link still reports "connected" but nothing gets through, the controller now notices and rejoins. Before, it could stay offline until it was restarted.
- **Radio:** a disabled or unresponsive radio is now reported as such, instead of as "busy". Entering receive mode is retried once before the radio is marked unavailable. Queued repeats are dropped while the radio is unavailable, instead of piling up.
- **Web UI:** the radio pin fields are read-only on the integrated board, because its pins are fixed.
- Queued radio jobs can be cancelled without cutting off a press that is already on air. LCD settings edits are saved when the wheel confirms them. SSDP replies are handled in the main loop.
- The updater, About screen and API all show the same version.

## Install

If you already run a v4.x LILYGO build on the standard layout, use the LCD updater or a firmware-only upload. Your settings and rolling-code counters are kept. Coming from another firmware, read [first installation](../first-install.md) first. Don't erase the flash or use a factory image.

Builds made from untagged sources identify themselves as development builds, and can't take stable updates from GitHub. This release is tagged, so devices running it can.

Protocol 2 is unchanged, so the cjkas-compatible Home Assistant integration 3.0.0 or newer still works. Calibration timing was measured with real radio presses on the board; calibrating both real shutters end to end is still being checked. The Wi-Fi forced-rejoin path is covered by native tests only so far.
