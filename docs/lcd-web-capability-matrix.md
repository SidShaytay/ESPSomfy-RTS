Inventory baseline: fetched main `fc5a2947928fdf855185f77ecaae69c00b677156` (2026-11-08). This is a **design inventory, not implementation or parity evidence**. The inventory was written before implementation and before live access. Current implementation and read-only deployment evidence are recorded in the audit below. No row authorizes RF, GPIO, model persistence, flashing, HA changes or hardware testing during development.

Sid's updated build decision: one shared full-feature `lilygo-t-embed-cc1101` firmware supports both CC1101 and CC1101 Plus. The unused Plus nRF24 module does not justify a second image. ## How to read the matrix

The current web application is `data-src/index.html` and `data-src/index.js`; `data-src/js/views.js` adapts the protocol model. Most operations use protocol 2 over `/ws`; the complete operation registry is `src/ProtoSchema.h:20`. Command requests use `parseShadeOp` / `ShadeRequests::run` (`src/ProtoOps.cpp:157`, `src/ShadeRequests.cpp:40`); edits use `expandEditPayload` and loop-owned `applyModelEdit` (`src/ProtoEdits.cpp:129`, `src/SomfyJson.cpp`); settings use `expandSettingsPayload` / `runDeviceOp` (`src/ProtoSettings.cpp:188`, `src/DeviceOps.cpp:217`). LCD code must call shared domain seams with typed data, never loopback HTTP, web handlers, or direct radio/rolling-code manipulation.

Current web authorization (`W`): None permits access; PIN or username/password security requires a token for all socket access and protected HTTP endpoints (`src/entryPoints/Web.cpp:96`, `src/outputs/ProtoSocket.cpp:265`, `src/HttpAccess.h:31`). Public assets/login context/login/SSDP do not provide privileged access. There is no web role distinction between everyday controls and administration. **W does not protect the encoder or Back button.**

LCD authorization (`V`, `C`, `A`, `B`): V = non-sensitive view; C = everyday control; A = local administration; B = browser-owned workflow under current web authentication, accepted by Sid as the equivalent for host file handling. Sid approved the same configured web credential for C and A, with 120-second inactivity expiry; after expiry, only STOP for the current authorized movement remains available until that movement stops or 30 seconds after the original session expiry, whichever comes first. Target/identity/membership/configuration changes end this exception; it never grants authority for later movement. All other commands require unlock. None mode remains open, with action-specific risky confirmations. PIN/password modes require unlock for controls and administration. Use an independent device-wide throttle with the current web schedule (fifth failure locks for 30 s, subsequent failures double up to 15 min, one-hour quiet reset); volatile failure state resets at reboot, an acknowledged limitation. Sid explicitly rejected a hybrid browser/LCD file-transfer transaction; no new LCD approval/staging/transfer session or transport feature is required. An asterisk means an action-specific confirmation showing the current entity and consequence. These describe the authorization requirements; current implementation evidence is in the audit.

Input abbreviations: list = rotary scroll, push select, Back return; edit = rotary changes a draft, push accepts field, explicit Save/Cancel; confirm = default Cancel and deliberate push on the named action. **Turning the wheel never sends a command or saves.** Every submission must revalidate IDs, RF identities, capabilities, membership, authorization, update/restore gates and queue capacity on the owning loop.

Tests named below are acceptance cases to add/extend, not tests already run or proofs of coverage. Existing useful host seams are `test/test_shaderequests`, `test/test_protoops`, `test/test_protoedits`, `test/test_protosettings`, `test/test_modeleditor`, `test/test_localui`, `test/test_configimport`, `test/test_secrets`, `test/test_loginthrottle`, `test/test_httpaccess`, `test/js/{model,views,client}.test.js`, and the adapter/runtime/capture/renderer harnesses invoked by `tools/test-local-ui-adapter.sh` and `tools/test-status-panel.sh`. Do not run `test/e2e` against an in-service controller.

## Settings, networking and integrations

The field list is derived from forms plus the complete typed save table (`src/ProtoSettings.cpp:31`), not labels alone. All settings reads/writes use W. Proposed location: Admin → Settings; A for reads that reveal credentials/identifiers and all writes; A* when security, radio, connection, GPIO or restart changes behavior. Every field gets draft/edit/save/cancel and shared validation. Existing `DeviceOps::runSave` (`src/DeviceOps.cpp:163`) ignores settings persistence return values and currently replies/logs saved even when storage fails. A truthful shared completion result, with rollback or an explicit partial applied/persisted outcome, must precede LCD Saved claims; reusing the current reply alone cannot meet acceptance. Common test S means: boundary/type/malformed input, no side effect on wheel/Back/timeout, saved vs queued/error differentiation, concurrent settings edit conflict, and persistence-failure feedback.

LCD-native flows must work standalone: the #12 GitHub updater supplies its own trusted metadata/download/staging service and its LCD confirmation without a companion file picker. ## Baseline and accepted decisions

The fetched baseline had three fixed targets, paired-RTS-only Up/Stop/Down controls and no dynamic catalogue. Those historical limitations describe the inventory's starting point; they do not describe the current Phase2 firmware. Preserve the shared-group STOP behavior and use the implementation audit for current status.

Sid selected the shared web credential for local controls/administration,120-second inactivity expiry, a device-wide attempt limit and the bounded continuing-movement STOP exception described above. Identifying/sensitive pages and screenshots follow the local authorization policy; credential changes revoke old authority. Existing recovery remains, with no whole-section LCD repair wizard.

Text entry is English-only, using bounded rotary input. Preserve unchanged existing UTF-8 bytes, show honest unsupported-character fallback and never reveal stored secrets. Secret editing uses explicit retain/replace/clear; protected captures include unlock, secret and sensitive diagnostic screens.

The browser owns clipboard, cache, backup/restore and manual files. The shared board firmware bundles web/controller/LCD software, while the GitHub updater is standalone on LCD. No companion-browser approval flow, SD feature or new transport is required.

Configured lamps show Light unavailable and preserve configuration. API-only raw-remote/estimated-position-correction operations are inventoried without adding casual LCD controls. Advanced chords and sensor simulation require explicit administrator review of physical effects; their implementation does not authorize executing them during development. Relay separate/Euro tilt modes remain configured, with their unsupported driver mapping disclosed in the audit.

This inventory defines acceptance requirements. Phase1/2 are integrated and flashed; see the [implementation audit](lcd-capability-audit.md) for row-level status, remaining Phase3/4 integration and explicit limitations. Native/compiler/renderer evidence and physical-board acceptance are separate. Firmware builds cannot establish heap fragmentation, combined TLS/staging/capture stress or real loop/SPI timing on hardware; those measurements remain a later explicitly authorized stage.
