# Staged firmware verification

`GitUpdateImage::verify()` validates caller-owned staged bytes without reading a partition or starting an update. The standalone GitHub installer and canonical manual firmware path will share it. This checkpoint alone enables no installer, startup call, route, network request or flash write.

An authenticated GitHub manifest supplies exact size, SHA256, source, version, shared profile, bundled compatibility and installed bootloader binding. A null manifest is the explicitly user-selected manual path: its embedded metadata establishes consistency, not GitHub publisher authentication. The supplied bootloader identity must have been separately attested; this verifier never provisions or changes it.

Checks include the canonical S3/DIO/16MB/80MHz header, 1–16 bounded segments, first-segment application descriptor magic and pinned IDF field, XOR checksum, exact appended SHA256 and absence of trailing bytes. The descriptor's version/project fields are framework values in the actual SDK, so they are not confused with the application's source version. The SDK OTA end check remains the final image validation authority before any future activation.

Exactly one schema-3 shared-profile marker, matching bootloader marker and bundled archive must lie within valid segment data. Stable or exact source-bound development identities are supported for manual files; GitHub manifests still require stable releases. Generic, retired, duplicate, malformed and inconsistent identities fail closed. Parser comparisons use split prefixes so activating the verifier does not add extra complete sentinel strings to its own firmware.

The archive manifest is limited to 16 KiB and 128 root public assets, with a 127-character path limit and aggregate packed payload of 0x180000 bytes. Records must be sorted and unique; plain/gzip shadows and private/nested paths are rejected. Every exact packed payload and manifest digest is checked. Required HTML/JS/CSS/version entries must exist; the source-version value fits 14 characters with at most 32 raw bytes. Gzip framing must match the canonical no-options/timestamp-zero form and its declared expansion must fit 8 MiB. The device does not inflate or interpret HTML: the reviewed release packager verifies complete gzip streams and the semantic bundled-mode marker, and GitHub's authenticated full image digest binds those packaged bytes.

The existing immutable bundle verifier now shares `UpdateSha256`, retaining 1 KiB hash chunks, watchdog-safe yielding, cooperative cancellation and complete hash cleanup. The staged parser rescans the small bounded manifest to detect aliases rather than allocate a 16 KiB name table on the internal worker stack. Failed/interrupted verification clears the output identity; it cannot leave an old candidate populated.

Run `CXX=g++ bash tools/test-update-image.sh` for local synthetic framing/profile/archive/hash/failure cases. Set `UPDATE_IMAGE_FIRMWARE` to an existing public local build artifact to verify those actual compiled bytes too. `bash tools/test-bundled-web.sh` retains the actual serving/version/hash/cancellation checks after the shared hash extraction. These are local/fake tests and build checks, not physical flash, rollback or motor qualification.
